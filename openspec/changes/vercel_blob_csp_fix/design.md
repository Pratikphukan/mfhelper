# Design: Allow Vercel Blob Uploads Through CSP

## Scope

Adjust only the Content Security Policy generated by the Vercel holdings importer page so the browser can send the PDF to Vercel's signed Blob upload URL.

## Current Failure

The page script obtains a signed URL from `/upload-token/presign`, then calls `fetch(presign.url, { method: 'PUT', ... })`. The Network screenshots show that the returned URL starts with `https://vercel.com/api/blob/`. The current `connect-src` permits `'self'` and `https://*.blob.vercel-storage.com`, so the browser rejects this request and displays `Failed to fetch`. No `/import` request is sent.

## Approved CSP Change

Add `https://vercel.com/api/blob/` to `connect-src`, retaining `'self'` and `https://*.blob.vercel-storage.com`. Leave script, style, form, frame, and other response-security policies unchanged.

The path-scoped source permits the observed Vercel upload endpoint. CSP ignores a source path after a redirect, while the existing Blob-storage host source permits the redirected storage request.

## Verification

- Add a regression test asserting the generated CSP includes the Vercel Blob API path and retains the existing allowed sources.
- Run the repository test suite as required by the repository instructions.
- Redeploy the PR branch and use a synthetic CAS PDF. Confirm Network shows the Blob `PUT` followed by `/import`, and the successful import persists the snapshot while removing the temporary PDF.

## Alternatives and Trade-offs

- **Allow all of `https://vercel.com`:** simplest and robust to endpoint path changes, but permits this page to make connections to any path on that origin.
- **Allow only `https://vercel.com/api/blob/` (approved):** matches the URL observed in Network and keeps the exception narrower; it may need adjustment if Vercel changes the upload URL path.
